# NTIP 0.2.0 release notes

**Simulation only, not for live dispatch.** A research prototype of an
advisory, human-in-the-loop triage platform for NG911 text and transcripts,
working on synthetic data only. Changes are listed in the
[changelog](../../CHANGELOG.md). 0.1.0 was prepared but never tagged (its
Release workflow had a defect fixed here), so this is the first tagged release.

## What is new since 0.1.0

- **Tenants:** incidents, replay runs and idempotency keys are scoped to a
  tenant, and another tenant's incident answers 404 (DDL-017).
- **NG911 interop:**
  - EIDO PIDF-LO locations are mapped;
  - NENA-STA-024 conveyance works in the subscriber role, with messages
    validated against NENA's pinned schema (DDL-018);
  - Texas A&M `ng911-dev` was reviewed for applicability.
- **Location level L3** against a NENA-format GIS reference layer, with a
  synthetic layer included.
- **Data management:**
  - optimistic concurrency per incident (DDL-016);
  - pooled PostgreSQL connections;
  - a read-and-append application role;
  - lawful, audited erasure with tombstones (DDL-019).
- **Operations:**
  - structured JSON logs;
  - Prometheus `/metrics`;
  - an explicit simulation-only deployment mode.
- **Replay and evaluation:**
  - stream replay with relative timing;
  - human-review replay (machine output vs the operator's decision);
  - an evaluation report screen.
- **Quality:**
  - published schema samples with compatibility tests;
  - automated accessibility tests;
  - an end-to-end workflow test;
  - CI run summaries;
  - weekly benchmarks;
  - workflow linting.

## Schema compatibility

- **2.4.0 → 2.6.0 is additive:**
  - 2.5.0 adds `tenant_id` on source events and replay runs (default
    `"default"`);
  - 2.6.0 adds `supplied_locations` on source events, `supplied_by` on location
    candidates, and `note` on interop field mappings.

  Every addition is optional. Since this release the claim is tested, not
  argued: `tests/test_schema_compatibility.py` checks every published sample,
  and documents without every field added since 2.0.0, against the current
  models and JSON Schemas.
- Earlier notes still apply: 1.x → 2.0.0 is breaking, and the v1 schemas
  remain published ([0.1.0 notes](0.1.0.md#schema-compatibility)).
- **Database:** migrations `0005` to `0008` are reversible.
  - `0005` renumbers incident versions;
  - `0006` adds the `ntip_app` role, which deployments should connect as;
  - `0007` adds tenant columns, with earlier rows belonging to `default`;
  - `0008` adds erasure tombstones and the flagged-transaction erasure rule.

- the full test suite against PostgreSQL 16;
- the dev and regression evaluation;
- the safety gate.

It attaches the reports, which record the commit's SHA.

supplied locations, which the curated set does not contain.

## Known limitations

- **Not validated for real use.** All data is synthetic and author-labelled,
  with no independent annotators or practitioner review.
- **Rules miss things on unseen data:** B0 under-triaged 2 of 9 critical cases
  on the held-out test split. The default `rules_only` mode keeps a human
  reviewer on every assessment.
- **B2** is implemented but not evaluated (needs authorisation to call a paid
  API). **B3** is not built.
- **Interop:**
  - conveyance covers the subscriber role only, validated against the message
    schema, not the standard's text;
  - persons and vehicles in EIDOs are deliberately unmapped;
  - no `ng911-dev` test applies.
- **Location:** L3 runs against a synthetic layer here, and L4 (LVF-style
  validation) is not built.
- **Access control:** tokens are static (no expiry, rotation or SSO). Rate
  limiting is per process.
- **Language:** English plus some Spanish.
- **Licence:** the repository has no licence yet.

The [traceability matrix](../traceability-matrix.md) tracks every design
requirement and its status.

## Reproducible demo

Requires Docker with Compose.

```sh
git checkout v0.2.0
docker compose -f infra/docker/docker-compose.yml up --build
```

- Dashboard: <http://localhost:8080>. Enter a development token such as
  `dev-operator`.
- API docs: <http://localhost:8000/docs>. Metrics: `GET /metrics` with a token.
- The stack runs L3 with the synthetic reference layer, so try
  "Smoke at 9 Birch Lane".
- For the B1 model in hybrid mode, prefix the command with
  `NTIP_MODEL=b1-tfidf-logreg NTIP_INFERENCE_MODE=hybrid_review`.

To reproduce the evaluation, see `backend/README.md` and the
[0.1.0 notes](0.1.0.md#reproducible-demo).
